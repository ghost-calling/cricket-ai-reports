
# Cricket AI Match Reports

This is a simple AI assisted scraper project that scrapes live cricket data.

## Live Demo

- **Landing page:** https://cricket-ai-reports.onrender.com/
- **Sample report (saved real output, no API call):** https://cricket-ai-reports.onrender.com/demo

The sample is a real report generated by the live `/report/<id>` endpoint and saved as `sample_report.json`, so the demo works even when the Gemini API is unavailable.

`/report/<id>` generates a fresh report with the Gemini API. On a fresh deploy, call `/scrape` first to load matches, since the free-tier database resets on every restart.

> Hosted on a free tier. The first request after idle can take 30-50 seconds while the server wakes up.

## What it does 

This project scrapes live match data from Cricbuzz. By capturing real-time metrics - including team scores , match status , venue and date information. It automatically generates an AI-powered match report.

## Architecture
Cricbuzz → scraper.py → SQLite database → Gemini API → Flask API

## Tech stack
- Python, Flask
- SQLite
- Google Gemini API (gemini-flash-lite-latest)
- BeautifulSoup/regex for scraping
- pytest

## How to run locally
1. Clone the repo
2. Create venv, install requirements.txt
3. Add your own GEMINI_API_KEY to a .env file
4. Run `python app.py`
5. Visit /scrape to fetch live matches, then /report/<id> for a report

## Key design decisions

While testing the AI report generation, I found the model would invent specific 
match details (fake in-progress scores, fictional tactical moments) when given 
incomplete stats. I fixed this by adding explicit constraints to the prompt: 
don't invent details not present in the data, and clearly state when detailed 
stats aren't available rather than filling the gap with plausible-sounding fiction.

Separately, I traced a related issue to stale test data still sitting in the 
database from earlier development — a good reminder that when AI output looks 
wrong, the data feeding it needs to be verified just as carefully as the prompt 
or the model itself.

## Known Limitations

- `/scrape` is public and can be triggered by anyone; a production version would protect it.
- Generated reports can include details not present in the source data (LLM hallucination). The prompt reduces this, but doesn't eliminate it.
- The SQLite database is ephemeral on Render's free tier.
